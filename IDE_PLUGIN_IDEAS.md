# Идеи плагинов под разные IDE JetBrains

Черновик идей. Локальный документ (не в публичном репозитории по умолчанию).

**Стратегическая рамка:** у нас уже есть переиспользуемое **ядро валидных синтетических данных**
(чистый Kotlin: IBAN/Luhn/VAT/BSN/ABN/TFN + тесты, per-country абстракция). Плагины ниже — это
разные **поверхности** над одним ядром под разные IDE и разные боли. «Переиспользует движок = ✅»
означает, что бизнес-логика уже написана и покрыта тестами, остаётся IDE-специфичный UX.

Лейн держим прежний: **QA / тест-данные / fintech / KYC / приватность**, чтобы покупатель был тот же.

## Детали

### 2. SQL Synthetic Seeder — DataGrip 💾
**Боль:** заполнить таблицу правдоподобными, но проходящими валидацию данными для ручного/нагрузочного теста.
**Что:** правый клик по таблице/схеме → «Seed N coherent rows». Читает колонки, сопоставляет типы/имена
(`iban`, `card_no`, `vat`, `dob`, `email`) с генераторами, вставляет N связных строк с сохранением
внешних ключей. Опционально — с невалидными вариантами для негативных тестов.
**Ров:** валидность чек-сумм + ссылочная целостность (согласованные FK, одна персона на строку).
**Монетизация:** одиночная вставка — free, bulk/по всему графу таблиц — paid.

### 3. PII Anonymizer / Repro Sanitizer — все IDE 🕶️
**Боль:** нужно приложить к багрепорту/тикету JSON/CSV/лог, но там реальные PII.
**Что:** выделяешь текст/файл → инспекция находит PII-подобные поля (имена, email, IBAN, карты, телефоны)
и заменяет на **синтетические, но валидные** эквиваленты, сохраняя формат и связность.
**Ров:** не просто «звёздочки», а рабочие валидные заменители — репро остаётся воспроизводимым. Сильный privacy-нарратив.
**Монетизация:** team-версия с правилами и словарями полей.

### 4. Secret & Card Leak Guard — все IDE 🛡️
**Боль:** реальные номера карт/IBAN/SSN случайно попадают в код, фикстуры, логи.
**Что:** инспекция + опциональный pre-commit хук, помечающая строки, похожие на **настоящие** PAN (Luhn + реальные BIN),
IBAN (mod-97 + реальная страна), SSN. Быстрый фикс: заменить на наш синтетический тестовый эквивалент.
**Ров:** отличает валидное-реальное от тестового (знаем тестовые BIN/зарезервированные диапазоны). Defensive security.
**Монетизация:** free для инди, team-политики — paid.

### 5. MRZ & Barcode Inspector — все IDE 🔎
**Боль:** дебажить KYC-парсинг MRZ/штрих-кодов без ручного пересчёта контрольных цифр.
**Что:** tool window: вставляешь строку MRZ (TD1/TD2/TD3) или полезную нагрузку PDF417/AAMVA — получаешь
разобранные поля и валидацию каждой контрольной цифры (что именно сломано). Идеальный **компаньон-ридер** к генератору MRZ из v1.1.
**Ров:** тот же эталонный код чек-цифр, что и в генераторе (`icao731CheckDigit` уже есть).

### 6–9, 13. Фикстуры под язык — PyCharm / WebStorm / GoLand / Rider / PhpStorm 🧪
**Боль:** faker-и в каждой экосистеме дают *правдоподобные*, но не проходящие валидатор данные.
**Что:** генерация идиоматичных фабрик/фикстур: `factory-boy`/`pytest` (Py), фабрики + MSW-хендлеры (TS),
`[]struct{}` табличные тесты (Go), классы + Bogus (C#), фабрики Laravel/Symfony (PHP). Из выделенного
типа/класса/таблицы — готовый билдер с валидными полями и негативными вариантами.
**Ров:** единственные фикстуры, которые проходят реальные чек-суммы; один движок — пять IDE.
**Монетизация:** free basic, pro (bulk, шаблоны с ограничениями, CI) — paid.

### 10. Compose/Espresso Preview Data — Android Studio 📱
**Боль:** `@Preview` и instrumented-тесты с «Lorem ipsum» не показывают реальные состояния fintech-экранов.
**Что:** провайдеры данных для `@Preview` (валидные IBAN/карты/персоны) и хелперы для Espresso/Compose-тестов;
right-click → вставить `PreviewParameterProvider` с связной персоной.
**Ров:** реалистичные банковские экраны на этапе дизайна; прямое пересечение с аудиторией Kassi (mobile/QA).

### 11. Checksum & Regex Playground — все IDE 🧮 (воронка)
**Боль:** быстро проверить IBAN/Luhn/VAT или regex, не выходя в браузер.
**Что:** tool window: вставляешь значение — мгновенно валидность по всем чек-суммам; отдельная вкладка — live-regex
по выделенному тексту. Бесплатный, лёгкий — **воронка** к платным генераторам.
**Ров:** офлайн, мгновенно, тот же проверенный код.

### 12. HTTP Client Data Injector — IDEA и IDE с `.http` 🌐
**Боль:** в JetBrains HTTP Client вручную подставлять тестовые карты/IBAN/токены.
**Что:** в `.http`-файлах автокомплит/интеншн «вставить валидный тестовый PAN/IBAN/BIC/персону» в тело запроса.
**Ров:** нативная интеграция с уже любимым инструментом; мгновенная ценность.

### 14. JMeter .jmx Toolkit — IDEA и все IntelliJ 🧵

**Статус:** записано в бэклог идей, **НЕ в работе**. Дата: 2026-08-16.
**Приоритет:** после Deep Link Lab / test-data keyboard; кандидат в JetBrains-каталог рядом с ISO 8583.
**Внимание:** идея вне общего лейна — ядро валидных данных не переиспользуется, покупатель другой (perf-инженеры).

**Ниша:** работа с JMeter test plans (.jmx) внутри IDE — без запуска отдельного JMeter GUI.

**Почему щель существует:**
- JMeter — самый распространённый нагрузочный инструмент в энтерпрайзе: широчайшая протокольная
  поддержка (JDBC, JMS, LDAP, SOAP и т.д.), огромная инсталлированная база и legacy-скрипты.
- .jmx — многословный XML: нечитаем в git diff, ревьюить изменения test plan в PR практически невозможно.
- JMeter GUI — отдельное тяжёлое Java-приложение, разработчики его не любят.
- **Ключевое:** у JMeter нет коммерческого вендора. Apache не будет раздавать бесплатный IDE-тулинг,
  в отличие от k6 (Grafana бесплатно даёт IntelliJ-плагин, VS Code extension, конвертеры — монетизирует
  облако) и Gatling (продаёт Enterprise сам). Конкурировать с бесплатным вендорским тулингом за
  k6/Gatling — тупик; у JMeter этого конкурента нет.

**Боли → фичи:**

| Боль | Фича плагина |
|---|---|
| .jmx нечитаем в code review | Human-readable diff / структурное сравнение двух .jmx |
| Нужен GUI чтобы понять структуру плана | Tree-view test plan прямо в IDE (read-only viewer как MVP) |
| Правки требуют запуска JMeter | Редактирование частых свойств (threads, ramp-up, endpoints, переменные) без GUI |
| Сравнение результатов прогонов — ручное | Просмотр/сравнение .jtl результатов, дельта по перцентилям |
| Pass/fail в CI требует обвязки (Taurus, Maven plugin) | Генерация CI-конфигов / threshold-гейтов |

**MVP:** read-only — tree-view .jmx + структурный diff для ревью. Это уже решает боль code review
и не требует полного понимания всех JMeter-компонентов.

**Монетизация:** freemium — viewer бесплатно (воронка + отзывы), diff/edit/results — платно.
Покупатель — энтерпрайз (perf-инженеры, QA-команды с легаси .jmx), привычен к платным
JetBrains-плагинам. Модель JetBrains Marketplace: подписка через маркетплейс.

**Риски / открытые вопросы:**
- [ ] Проверить маркетплейс глубже: есть ли уже .jmx-плагины (syntax highlight не считается — смотреть именно viewer/diff)
- [ ] Насколько велика доля JMeter-команд, работающих в JetBrains IDE (perf-инженеры часто живут в самом JMeter GUI)
- [ ] Тренд: энтерпрайз медленно мигрирует на k6/Gatling — ниша сжимающаяся, но legacy-хвост длинный
      (аналогия с ISO 8583: старое ≠ мёртвое)
- [ ] Формат .jmx стабилен между версиями JMeter? (риск поддержки)

**Fit-оценка (честная):**
- ✅ Энтерпрайзный legacy без вендора-конкурента — тот же паттерн, что ISO 8583
- ✅ Парсинг формата — сильная сторона (QA, форматы, structured data)
- ✅ Низкий maintenance: парсер XML, без серверов
- ⚠️ Нагрузочное тестирование — не основной домен (мобильный QA/финтех)
- ⚠️ Каталог JetBrains-идей уже есть; это дополнение, не замена ISO 8583

**Вердикт:** записать — да. Влезать сейчас — нет. Пересмотреть после релиза текущих Kassi-продуктов.

## Как я бы приоритизировал (2 недели каждая, по одной)

1. **#11 Checksum & Regex Playground** (S, free) — быстрый публичный вход, воронка, минимум риска.
2. **#5 MRZ & Barcode Inspector** (M) — синергия с v1.1, читатель к нашему писателю.
3. **#4 Secret & Card Leak Guard** (M, security) — отдельная аудитория, defensive-нарратив.
4. **#2 SQL Synthetic Seeder** (M, DataGrip) — первая явно платная ценность (bulk).
5. **#6–9 фикстуры под язык** — по спросу; один движок разворачивается на 4–5 IDE.

**Принцип тот же, что в основном роадмапе:** сначала depth (один проверенный движок), потом breadth
(много IDE-поверхностей); одна вещь доведена и залистена до начала следующей.

**#14 (JMeter .jmx Toolkit)** в этот список сознательно не входит: другой лейн, ядро не переиспользуется —
бэклог, пересмотр после релиза текущих продуктов.
