# Engineering principles

How to work in this repo. Adapted from the Karpathy engineering principles
(multica-ai/andrej-karpathy-skills). Read before making changes.

## 1. Think before coding
- State assumptions explicitly; if uncertain, ask rather than guess.
- If there are multiple reasonable interpretations, present the tradeoffs — don't pick silently.
- If a simpler approach exists, say so; push back on unnecessary complexity.
- If something is unclear, stop and name what's confusing.

## 2. Simplicity first
- Build only what was asked. No speculative features, flags, or configurability "for later".
- No abstractions for single-use code.
- Skip error handling for genuinely impossible states.
- Senior-engineer test: would a senior call this overcomplicated? If so, simplify.

## 3. Surgical changes
- Change only what the task requires. Don't "improve" adjacent code, comments, or formatting.
- Match the surrounding style even if you'd personally do it differently.
- Remove only the dead code your change introduced — not pre-existing cruft (file that separately).
- Every changed line should trace back to the request.

## 4. Goal-driven, verified execution
- Define verifiable success criteria up front; turn vague asks into concrete tests.
- For multi-step work, outline the plan with verification steps.
- Loop until success is *demonstrated* (build + tests pass), not assumed.

## Project specifics

- **What this is:** a JetBrains/Android Studio plugin (Kotlin) that generates
  *spec-valid* banking/KYC test data — data that passes real validators (mod-97,
  Luhn, national checksums) — plus deliberately invalid variants. Offline,
  deterministic, no server, no real PII.
- **The rule that defines the project:** every generator is backed by a unit test
  that *proves* validity (the checksum actually verifies). A new generator without
  a passing validity test is incomplete — this is principle #4 made concrete.
- **Build/verify:** `./gradlew build` and `./gradlew verifyPlugin` (must be
  Compatible) before shipping. Prefer non-deprecated IntelliJ Platform APIs.
- **Commits/PRs:** never add "Generated by Claude Code" / "Co-Authored-By: Claude"
  anywhere. Branch → PR → CI green → merge; don't commit/push to the default
  branch directly.
